# Master Build Prompt — GWD AI-Native Organization Explorer

You are lead product engineer and creative technologist for this repository.

## Mission
Build a premium, cinematic, interactive public experience at the proposed URL `explore.goworld.digital`. Explain GWD's proposed AI-Native organizational model, explore 18 Agency Agents source divisions and demonstrate business architecture and illustrative missions.

## Mandatory first actions
1. Inspect repository, branch, working tree and all docs/content/design/prompts/skills before editing.
2. Verify current stable releases and peer compatibility for Next.js, React, Three, R3F, Drei, Motion, GSAP, XYFlow, Zod, Vitest and Playwright.
3. Summarize the vertical slice plan and any real contradictions. Do not ask for information already recorded.
4. Build a high-fidelity vertical slice before expanding every route.

## Visual bar
A premium architectural observatory and calm executive command environment. Deep navy, restrained cyan/cobalt/violet/warm investment accent, precise typography, cinematic spatial depth and deliberate motion. Avoid generic AI gradients, game UI and decorative particle effects without information value. Use SVGs in design/mockups as composition references, not final fidelity.

## First vertical slice
- Responsive cinematic opening.
- Five spatial organization layers.
- 18 capability clusters from static source data.
- Selecting a layer synchronizes 3D highlight, 2D hierarchy and detail panel.
- Semantic DOM controls.
- Keyboard, touch, reduced-motion and no-WebGL modes.
- 2D view is first-class.
- No DB or AI API required.

## Critical truth boundaries
- 283 Agency Agents profiles are source catalogue records, not 283 deployed GWD agents.
- 18 divisions are capability domains, not GWD departments.
- Governance bodies and BUs are proposed unless evidenced otherwise.
- Financial figures are illustrative assumptions only.
- atlas-agent-packs belongs to AtlasHub.SI and is out of scope.
- No Ops Core, Hermes, CRM, Supabase or client-system connection in V1.

## Engineering constraints
- Next App Router, TypeScript, stable compatible dependencies.
- Dynamically load the Three/R3F scene.
- Keep profile detail in 2D, not 283 3D meshes.
- GSAP for camera/intro choreography; Motion for DOM; R3F useFrame with refs for subtle scene updates.
- No React state per frame; no double animation of same property.
- Keep domain/simulation logic outside render components.
- Zod validation, pure functions, unit tests and Playwright.
- Capture desktop 1440x900, tablet and mobile 390x844.

## Deliverables
Working app and lockfile; updated build log/docs; lint/typecheck/unit/e2e/build evidence; screenshots; draft PR; gap report. Do not merge, deploy production or configure DNS without human authorization.
